# TicketFlow — instruções para agentes de código

> Este arquivo existe para que agentes procurando por `docs/CLAUDE.md` encontrem o caminho certo. O conteúdo real não vive aqui — vive em `docs/PROJECT-MAP.md`, que já cumpre esse papel e é mantido revalidado a cada auditoria.

## Leia nesta ordem

1. **`docs/PROJECT-MAP.md`** — índice operacional do projeto (estrutura, rotas, funções do banco, convenções). Comece por aqui.
2. **`docs/TPS.md`** — especificação de produto oficial.
3. **`docs/AUDITORIA.md`** — estado técnico vivo: o que está resolvido, o que está pendente, e por quê.
4. **`docs/skills/ticketflow-development.md`** — convenções específicas de desenvolvimento (migrations, reconciliação repo/banco, como registrar problemas novos).

## Regra permanente do repositório

Documentação não é apagada quando fica desatualizada — é corrigida com uma nota explicando o que mudou, preservando o histórico. Ver `docs/CHANGELOG.md` e `docs/AUDITORIA.md` para exemplos desse padrão.
